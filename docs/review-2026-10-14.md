## Should-fix

### 1. A crew tower merges two different friends' wins when their names match
`Strata/Models/BlockMerge.swift:127`, `Strata/Views/Crews/CrewTowerModel.swift:86`

`perPerson` compares `look.sender`, which is the display line
(`CrewTowerModel.senderLine`), not a profile id. Two friends with no name both
read "A friend", and two friends called "Sam" both read "Sam", so their touching
same-colour wins draw as one shape. That is exactly what spec 2.4 kept crews
from merging for.

- **Scenario:** two members never set a name. Each logs a green win and they
  land side by side. The tower shows one green run, read as one person's.
- **Fix:** carry the sender's profile id on `PlacedBlock.Look` (it is already
  on the `SharedWin`) and merge on that, plus `isMine`.

### 2. A line that never sends stops saying so after about a minute
`Strata/Social/SocialStore.swift:1406` (`isUnsent`), `:2065` (`dropHopeless`), `Strata/Social/CrewOutbox.swift:40`

`isUnsent` is true only while the line's write is still in the outbox. A
non-transient failure is counted, and after 20 counted tries the outbox drops
the entry. From then on the line is drawn at full opacity with no "That didn't
send" under it. A tap no longer retries, because `isUnsent` is false.
`retry`'s doc says "A write the outbox gave up on is put back", but no path
reaches it once the entry is gone.

- **Scenario:** the save keeps failing with a record error. For about a minute
  the line says "That didn't send. Try once more." Then it looks sent. Nobody
  else ever sees it, and the next fetch may quietly remove it.
- **Fix:** keep a set of given-up message names (from `dropHopeless`, which
  already returns them) and have `isUnsent` read it too. Or don't let
  `dropHopeless` drop `.message` puts by your own phone.

### 3. On Wins, a friend's win sent from the chat notifies twice
`Strata/Views/Crews/WinsChatBanner.swift:35`, `Strata/Social/SocialStore.swift:1443-1452`, `Strata/Views/Crews/CrewsListView.swift:54-60`

The sender's push for a win line is suppressed (`pingMessage`, `:2498`), and
`CrewNotifications.chatNews` skips it (`:255`). Three receiver-side paths still
treat it as chat news:
- `ChatBannerWatch.arrived` doesn't filter `isWinLine`. The win's own push
  (kind `.win`, no `chatKey`) shows as a system banner in `willPresent`, and
  then `WinsChatBanner` slides "Sam: Gym" over the tower as well.
- `chatNews(in:)` (`hasUnreadChat`) counts it, so the chat dot lights for a
  win the tower already shows. Commit 3662613 says it "is not counted as chat
  news".
- The Crews list's "into the chat when a message is the news" then opens the
  chat instead of the tower for that win.

- **Fix:** filter `!store.isWinLine($0)` in `ChatBannerWatch` (pass a
  predicate in, so it stays pure) and in `chatNews(in:)`.

### 4. While Wins is listening, a chat push can disappear with nothing shown
`Strata/Social/StrataAppDelegate.swift:212-216`, `Strata/Views/Crews/WinsChatBanner.swift:91`

`willPresent` returns `[]` for every chat push while `ChatBanner.isListening` is
true, on the promise that the line will appear over the tower. It won't in
these cases:
- `pushed()` fetch fails or is slow (two-minute window).
- The sender has no member record on this phone yet (`crew.member(...)` is nil,
  so the banner draws nothing).
- The line is a doodle or picture waiting on the photo check
  (`messages(in:)` hides it).
- A sheet that `ringIsClear` doesn't list is over Wins.

- **Scenario:** a new member's first line arrives while you're on Wins. No
  system banner, no in-app banner.
- **Fix:** suppress the system banner only after the in-app banner has the
  line. For example, return `[.list]` (Notification Center only) rather than
  `[]`, or have `WinsChatBanner` post the system banner as a fallback when its
  `member` lookup fails.

### 5. The crew head arena's "no air" rule squeezes every head into one head-height under the header
`Strata/Views/Crews/CrewHeadArena.swift:642-644`

When the roof is off screen, `skyline` becomes `TowerSkyline()`, which has
`tops` all 0. `roof` is then read from that empty skyline
(`probe.hasMeasured`), giving 0, so `upper = max(lower + side, min(0 - …, …))`
equals `lower + side`. The drift band is one head tall right under the
header, which is the 2026-10-02 "eight heads lined up along the top edge"
bug.

Separately, an empty skyline has no ground, so a thrown head falls to the
screen bottom (`bounds.maxY`). That is over the new `ChatRestBar`, which is
not in `parking.controls` (the old `"chat"` control went with the button), so
a resting head can sit on the Message field.

- **Fix:** compute `roof` from `bounds.maxY` (or the drawer's top) when
  `skyline` is the no-air one. Add the drawer's frame to `parking.controls` so
  it is an obstacle, or set the floor at its top.

### 6. A still hold and release on a crew block can send a reaction
`Strata/Views/FlippableBlockView.swift:433`, `Strata/Views/Crews/CrewTowerView.swift:498-511`, `:519`

`BlockHold` always reports `.ended(at)` with the finger's location. `mark(at:)`
accepts points up to 36pt below the bar, and the bar sits 8pt above the block
(`barCenter`), so the top 28pt of the held block is inside the pick band. A
finger held there and lifted without sliding picks whichever glyph is above
it: usually a middle quick reaction, or "+".

- **Scenario:** you hold near the top of a friend's block to see the bar, lift
  without sliding, and 🔥 is sent. The friend is pinged.
- **Note:** the old SwiftUI drag also reported a location once the finger
  jittered, so this may predate tonight. The UIKit recognizer now does it
  every time. Verify on a device.
- **Fix:** on `.ended`, pick only if a `.moved` set `hovered` (track a "slid"
  flag from `.began`), or start the band at the bar's bottom edge.

### 7. Plan on a crew's + sheet fails silently
`Strata/Views/AddWinSheet.swift:115` (`offersPlanning`), `:1386` (`propose(to:)`)

`offersPlanning` doesn't check `SocialStore.canReply()`, but `sendPlan` goes
through `send`, which refuses without it (`SocialStore.swift:1206`). On
refusal, throttling (two lines inside a second) or the daily limit,
`propose(to:)` removes the line and puts the words back, with no message. The
chat's own plan path says "Try other words" or "That's plenty for today"
(`CrewChatSheet.answer`).

- **Scenario A:** someone whose writing is off taps Plan, types a line and
  presses Return. The line flashes and vanishes.
- **Scenario B:** typing two plan lines fast drops the second.
- **Fix:** gate `offersPlanning` on `canReply()` when `planCrew != nil`, and
  show the same three alerts the chat shows.

### 8. "Earlier Today" undo restores a five-second-old snapshot
`Strata/Views/AddWinSheet.swift:769-777`

Undo calls `CrewSync.setCrews(for: log, to: holding)` with `holding` captured
before the send. `SocialStore.setCrews` withdraws from every crew in the
current holding that isn't in that snapshot. Today the window is five seconds
and the risk is small. But the undo's intent is "take it out of this crew",
and a snapshot can also pull it out of a crew ticked meanwhile (an Edit
sheet, a second Earlier Today press on another crew).

- **Fix:** have Undo withdraw only the one crew:
  `Task { await SocialStore.shared.withdraw(winID: log.id, from: crewID) }`.

It also captures the `HabitLog`. A win deleted inside the five seconds hands a
deleted model to `ownWin`, so capture the id and refetch.
